# Configuration reference

PrzmTerm keeps its settings in plain [TOML](https://toml.io) files in one
folder. The app writes them, but they can also be written by hand,
generated by scripts, kept in Git, or synced between computers. This page
describes every file and key. It also states what stays compatible from
1.0 onwards.

## Where the settings live

PrzmTerm looks for the settings folder (`<config>` below) in this order:

1. `$PRZMTERM_HOME`, when the variable is set.
2. The folder chosen in *Settings folder…*. Its path is kept in
   `location.toml` in the system folder (next item), and that is the only
   file left there.
3. The system folder for application settings:

   | System | Folder |
   | --- | --- |
   | Linux | `~/.config/przmterm` |
   | macOS | `~/Library/Application Support/przmterm` |
   | Windows | `%APPDATA%\przmterm` |

```text
<config>/
  defaults.toml          global settings for every session
  sessions/              one file per session, folders as directories
    folder.toml          settings for everything below (optional)
    core-sw-01.toml
    Cisco/
      folder.toml
      edge-rtr-01.toml
  buttons.toml           the button bar
  keymap.toml            keyboard shortcuts (only when changed)
  keywords/              keyword highlighting sets, one file each
  scripts/               scripts (.rhai) named without a folder
  preferences.toml       the app's own preferences
  vault.toml             the encrypted password vault
  known_hosts            SSH host keys (OpenSSH format)
  logs/                  session logs with a relative file name
  backups/               copies taken before a restore
```

Every file is optional: a missing file means its defaults. Passwords are
never in these files. They go to the system keychain or to the encrypted
vault.

## Compatibility

From 1.0.0, every 1.x release keeps the promises below. They cover the
files on this page and the `.przm` backups and exports.

**Older files keep working.** A 1.x release reads every file written by an
earlier 1.x release and by 0.9. Every key on this page keeps its name, its
type and its meaning. Releases may add keys, and add values to a key that
takes a choice (`protocol`, `cursor`…). Renaming or removing a key takes a
new major version. Names used before 1.0 (`[[tab]]` in `buttons.toml`, for
example) are read as well.

**Newer files open in older versions.** A key that a version does not know
(written by a newer version, or misspelt) is left out, and the file is
still used:

- for `defaults.toml`, `folder.toml` and session files, the status line
  under the session list counts the files with problems, and its tooltip
  names the keys that were left out;
- for `buttons.toml`, the note shows on the button bar;
- for `keymap.toml`, the note shows in *Keyboard shortcuts…*;
- for keyword sets, the note shows in the terminal of the session that
  uses the set.

When that older version then saves the file (after an edit in the
settings, for example), the keys it did not know are not written back. A
value an older version does not know for a key it does know (a protocol
added later, say) cannot be left out the same way: that file shows as an
error until it is opened with a version that knows the value.

**The vault says which version wrote it.** `vault.toml` carries a format
version. A PrzmTerm that finds a newer format version refuses to open the
vault rather than guess, and leaves the file untouched.

Not covered: the layout of log files, the files in `backups/`, and
anything a script writes.

## Sessions, folders and defaults

Session settings come in three layers, and each one overrides the one
before:

1. `defaults.toml`: the global settings (*Global settings* in the app).
2. Each `folder.toml` from `sessions/` down to the session's folder.
3. The session's own file.

A session is `sessions/<path>/<name>.toml`. The file name (without
`.toml`) is the session's name, and the directories are its folders. Names
cannot contain `/ \ : * ? " < > |`, cannot start with `.`, and `folder` is
reserved for folder settings.

All three layers take the same keys. A key that is not set comes from the
layer before, and then from PrzmTerm's own default. For text keys, `""`
turns off a value set by a layer before (a `keywords` set, a `credential`,
an `anti_idle` text…). `[[forward]]` and `[[trigger]]` are lists: a layer
that has any replaces the whole list from the layers before.

```toml
protocol = "ssh"
host = "10.0.0.1"
port = 22
username = "admin"
keywords = "Cisco"
auto_reconnect = true

[terminal]
font_size = 15
background = "#101418"

[log]
enabled = true
path = "%S-%Y%M%D.log"

[[forward]]
type = "local"
listen = "8080"
target = "10.0.0.5:80"

[[trigger]]
match = "--More--"
send = ' '
```

### Connection

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `protocol` | `"ssh"`, `"telnet"`, `"serial"` or `"local"` | `"ssh"` | How to connect. `local` opens a shell on this computer. |
| `host` | text | — | Host name or address. Required for `ssh` and `telnet`. |
| `port` | number | 22 for SSH, 23 for Telnet | TCP port. |
| `username` | text | asked at login | User name. |
| `credential` | text | none | The name of a [vault](#password-vault-vaulttoml) entry whose user name, password and key passphrase are used to log in. |
| `identity_file` | path | the agent's and `~/.ssh` keys | SSH private key, tried before the others. `~` is expanded. |
| `save_password` | `true` or `false` | not set: ask | Keep passwords in the system keychain: `true` always, `false` never. |
| `keepalive` | seconds | 30 | Seconds between SSH keepalives or Telnet NOPs. `0` turns them off. |
| `auto_reconnect` | `true` or `false` | `false` | Reconnect when the connection drops or cannot be made. |
| `jump_host` | text | none | SSH: connect through this server first. Either the name of another session or `user@host:port`. That session's own jump host is used too. |
| `legacy_algorithms` | `true` or `false` | `false` | SSH: also offer old algorithms (SHA-1 key exchange, CBC, HMAC-SHA1, DSA) for old equipment. |
| `x11_forwarding` | `true` or `false` | `false` | SSH: show remote graphical programs on this screen (`ssh -X`). |
| `debug` | `true` or `false` | `false` | SSH: show each step of the connection and login (like `ssh -v`). |

### Serial port

Used when `protocol = "serial"`.

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `serial_port` | text | — | Required. `/dev/ttyUSB0`, `COM3`, `/dev/cu.usbserial-…` |
| `baud_rate` | number | 9600 | Speed. |
| `data_bits` | 5 to 8 | 8 | Data bits. |
| `parity` | `"none"`, `"odd"` or `"even"` | `"none"` | Parity. |
| `stop_bits` | 1 or 2 | 1 | Stop bits. |
| `flow_control` | `"none"`, `"software"` or `"hardware"` | `"none"` | `software` is XON/XOFF, `hardware` RTS/CTS. |

### Automation

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `keywords` | text | none | Keyword set used to highlight the output: `<config>/keywords/<name>.toml`. |
| `logon_script` | text | none | Script run each time the session connects. A bare name is looked for in `<config>/scripts`; a full path (or `~/…`) is used as it is. |
| `anti_idle` | one character | none | Sent (without Enter) after `anti_idle_interval` seconds without typing, so the far end keeps an idle session open. |
| `anti_idle_interval` | seconds | 60 | `0` turns anti-idle off. |
| `scp_shell` | text | the login shell | The shell SCP file browsing runs its commands in: `/bin/bash`, `sudo su -`… |

### `[[forward]]`: SSH tunnels

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `type` | `"local"`, `"remote"` or `"dynamic"` | `"local"` | `local` is `ssh -L` (a port here reaches `target` from the server). `remote` is `ssh -R` (a port on the server reaches `target` from here). `dynamic` is `ssh -D` (a SOCKS proxy here). |
| `listen` | text | — | Required. A port (`8080`) or `address:port` (`127.0.0.1:8080`, `0.0.0.0:8080`). |
| `target` | text | — | `host:port`, required for `local` and `remote`. IPv6 hosts go in brackets: `[::1]:22`. |

### `[[trigger]]`: automatic answers

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `match` | text | — | Text to look for in the output. |
| `regex` | `true` or `false` | `false` | `match` is a regular expression. |
| `send` | text | `""` | What to type when it shows up, with the [escapes](#escapes-in-send). |
| `once` | `true` or `false` | `false` | Only the first time per connection. |

### `[terminal]`

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `term_type` | text | `"xterm-256color"` | Terminal type announced to the server. |
| `scrollback` | number | 10000 | Lines kept above the screen. |
| `font` | text | built-in (Hack) | An installed monospace font family. `""` is the built-in one. |
| `font_size` | 8 to 36 | 14 | Font size in points. |
| `cursor` | `"block"`, `"underline"` or `"bar"` | `"block"` | Cursor shape. |
| `cursor_blink` | `true` or `false` | `false` | Blinking cursor. |
| `cursor_color` | `"#rrggbb"` | `"#6ec8ff"` | Cursor colour. `""` is the default one. |
| `background` | `"#rrggbb"` | `"#181a1f"` | The terminal's background. `""` is the default one. |
| `foreground` | `"#rrggbb"` | `"#d8dee9"` | The colour of plain text. `""` is the default one. |

### `[log]`

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `enabled` | `true` or `false` | `false` | Log everything shown to a file. |
| `path` | text | `"%S-%Y%M%D-%h%m%s.log"` | The file name, with the codes below. A relative name goes in `dir`. |
| `dir` | path | `<config>/logs` | Folder for relative file names. `~` is expanded. |

| Code | Becomes |
| --- | --- |
| `%S` | session name |
| `%H` | host (or serial port) |
| `%Y` `%M` `%D` | year, month, day |
| `%h` `%m` `%s` | hour, minute, second |
| `%%` | a `%` |

Characters that cannot be in file names are replaced with `_` in the
session name and the host.

### `[mcp]`: AI assistants

What an AI assistant connected through `przm mcp` may do with the session.

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `access` | `"none"`, `"read"` or `"full"` | `"none"` | `none`: not listed and cannot be opened. `read`: opened and read, nothing typed. `full`: commands and scripts too, except the blocked ones. |
| `block` | list of regular expressions | a built-in list | Lines matching any of them are never sent (case ignored). The built-in list stops restarts, erasing configuration or disks and deleting files. `[]` blocks nothing. |

### Escapes in `send`

`send` (in triggers, buttons and shortcuts) understands these escapes:

| Escape | Sends |
| --- | --- |
| `\r` | Enter |
| `\n` | line feed |
| `\t` | Tab |
| `\e` | Escape |
| `\p` | nothing: waits one second |
| `\\` | a backslash |
| `{vault:NAME}` | the password of the vault entry NAME |
| `{vault:NAME:username}` | its user name |
| `{vault:NAME:passphrase}` | its key passphrase |

Write `send` in single quotes (`'show run\r'`) so TOML keeps the
backslashes for PrzmTerm.

The `{vault:…}` pieces work in buttons and shortcuts: the file names the
entry, and the secret stays in the encrypted [vault](#password-vault-vaulttoml).
When the button or shortcut is used, PrzmTerm asks for the master password
if the vault is locked, then types the value. If the entry or the field is
missing, nothing is sent. Triggers do not type vault entries.

## Button bar: `buttons.toml`

Buttons come in groups. The bar shows one group at a time, chosen from the
list at its left.

```toml
[[group]]
name = "Cisco"

[[group.button]]
label = "Interfaces"
send = 'show ip interface brief\r'

[[group.button]]
label = "Save"
send = 'copy run start\r\p\r'
description = "Saves the running configuration"

[[group.button]]
label = "Backup"
script = "cisco-backup.rhai"
tooltip = false
```

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `group.name` | text | — | The group's name. |
| `group.button.label` | text | — | The text on the button. |
| `group.button.send` | text | `""` | What the button types into the session that has the keyboard, with the [escapes](#escapes-in-send). |
| `group.button.script` | text | none | A script to run instead of sending text. A bare name is looked for in `<config>/scripts`. |
| `group.button.description` | text | none | Shown when the pointer rests on the button. |
| `group.button.tooltip` | `true` or `false` | `true` | Show the description (or what the button sends) under the pointer. |

Files written before 1.0 say `[[tab]]` and `[[tab.button]]` for a group and
its buttons. They are read the same, and saved with the new names.

## Keyboard shortcuts: `keymap.toml`

The file exists only once the shortcuts have been changed in *Keyboard
shortcuts…*. It then holds every shortcut. Without it, the built-in ones in
the table below apply.

```toml
[[key]]
keys = "Cmd+Shift+T"
command = "new_tab"

[[key]]
keys = "F5"
send = 'show ip interface brief\r'

[[key]]
keys = "Alt+1"
script = "cisco-show.rhai"

[[key]]
keys = "Ctrl+Alt+I"
button = "Cisco/Interfaces"
```

| Key | Type | Meaning |
| --- | --- | --- |
| `keys` | text | The keys, joined with `+`. The modifiers are `Cmd` (⌘ on macOS, Ctrl elsewhere), `Ctrl` (always the Control key), `Alt` (Option on macOS) and `Shift`. The key itself is a letter, a digit, or a name such as `F5`, `Tab`, `Enter`, `Space`, `Plus` or `PageUp`. |
| `command` | text | An app command from the table below. |
| `send` | text | Text to type, with the [escapes](#escapes-in-send). |
| `script` | text | A script to run. |
| `button` | text | A button to press, as `Group/Label`. |

Each shortcut has `keys` and exactly one of `command`, `send`, `script` and
`button`.

| Command | Does | Built-in shortcut |
| --- | --- | --- |
| `new_tab` | New tab (same session) | `Cmd+Shift+T` |
| `new_shell_tab` | New PrzmTerm tab | `Cmd+Shift+N` |
| `close_pane` | Close pane | `Cmd+Shift+W` |
| `close_tab` | Close tab | — |
| `next_tab` | Next tab | `Ctrl+Tab` |
| `previous_tab` | Previous tab | `Ctrl+Shift+Tab` |
| `split_grid` | Split: grid | `Cmd+Shift+G` |
| `split_columns` | Split: side by side | `Cmd+Shift+D` |
| `split_rows` | Split: stacked | `Cmd+Shift+E` |
| `separate_panes` | Separate panes into tabs | — |
| `clone_session` | Clone session | — |
| `reconnect` | Reconnect | — |
| `disconnect` | Disconnect | — |
| `send_break` | Send BREAK | `Cmd+Shift+B` |
| `toggle_sessions` | Hide / show the session list | `Cmd+Shift+S` |
| `toggle_buttons` | Hide / show the button bar | — |
| `toggle_log` | Start / stop the log | — |
| `run_script` | Run a script… | — |
| `stop_script` | Stop the script | — |
| `script_guide` | Script guide | — |
| `open_sftp` | File browser (SFTP) | — |
| `open_scp` | File browser (SCP) | — |
| `send_files` | Send files (Zmodem, Ymodem, Xmodem) | — |
| `receive_files` | Receive files (Zmodem, Ymodem, Xmodem) | — |

## Keyword highlighting: `keywords/<name>.toml`

Each file is one set, named after the file. A session uses a set through
its `keywords` key.

```toml
match_case = false

[[rule]]
text = "down"
color = "#ff4040"

[[rule]]
regex = '\b\d{1,3}(\.\d{1,3}){3}\b'
color = "#ff55ff"
background = "#202020"
bold = true
```

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `match_case` | `true` or `false` | `false` | `Down` and `down` differ only when true. |
| `rule.text` | text | — | A word or phrase, matched as a whole word: `up` colours "up" and "link-up", not "backup". |
| `rule.regex` | text | — | A regular expression (lookaround allowed), used instead of `text`. |
| `rule.color` | `"#rrggbb"` | the text's own | Text colour. |
| `rule.background` | `"#rrggbb"` | none | Background colour. |
| `rule.bold` | `true` or `false` | `false` | Bold. |

Where matches overlap, the longest wins (`admin-down` over `down`). On equal
length, the earlier rule wins.

## App preferences: `preferences.toml`

The app's own settings, not those of sessions.

```toml
check_for_updates = true
look = "dark"
```

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `check_for_updates` | `true` or `false` | `true` | Look for a newer release on GitHub when PrzmTerm starts. |
| `look` | `"dark"`, `"light"` or `"system"` | `"dark"` | The interface's look (*Appearance…*). `system` follows the computer's mode. |

A broken file is read as the defaults: preferences never stop PrzmTerm from
starting.

## Password vault: `vault.toml`

User names, passwords and key passphrases, encrypted with a master
password. The file is TOML, but only its header can be read:

| Key | Meaning |
| --- | --- |
| `format` | Always `"przmterm-vault"`. |
| `version` | The format version, `1`. |
| `kdf` | `"argon2id"`: how the key is made from the master password. |
| `cost` | Argon2id's `memory` (KiB), `iterations` and `parallelism`. |
| `salt`, `nonce` | Base64. |
| `data` | The entries, encrypted with XChaCha20-Poly1305 (Base64). |

The header is authenticated with the data. Changing the costs or the salt
makes the vault fail to open, rather than open with weaker settings. Each
entry has a `name`, which sessions refer to with `credential = "<name>"`,
and a `username`, a `password` and a `passphrase`. Edit the vault in the
app (*Password vault…*), never by hand.

## Other files and folders

| Path | What it is |
| --- | --- |
| `location.toml` | Only in the system folder: `path = "…"`, the settings folder chosen instead. |
| `known_hosts` | SSH host keys PrzmTerm has accepted, in OpenSSH's `known_hosts` format. |
| `scripts/` | Scripts (Rhai, `.rhai`) named without a folder in `logon_script`, buttons and shortcuts. |
| `logs/` | Logs whose `path` is relative and with no `dir` set. |
| `backups/` | The configuration as it was before each restore, as `.przm` files. |

## Backups and exports: `.przm`

*Back up settings…* and *Export session…* write one `.przm` file, which is
TOML too:

```toml
kind = "backup"              # or "export"
version = "1.0.0"            # the PrzmTerm that wrote it
created = "2026-11-10 09:30"

[[file]]
path = "sessions/core-sw-01.toml"
content = '''
host = "10.0.0.1"
'''
```

- A **backup** holds `defaults.toml`, the session files and folders,
  `buttons.toml`, `keymap.toml`, the keyword sets, the scripts,
  `known_hosts` and the vault (still encrypted). Restoring it puts every
  file back, after saving the current configuration in `backups/`.
- An **export** holds the chosen sessions and folders. Importing it adds
  them under a new folder; nothing is replaced.

Passwords kept in the system keychain are in neither.
